## 平台是什么

`backend-module-generator` 是企业内部**低代码开发平台的基础技能**。它从 JSON 定义生成 MD 模块 SQL（`md_module` / `md_field` / `md_form` / `sys_resource` / `comm_dictionary` 等），后续所有功能都基于这个基础生成模型数据后再做定制化开发。

**适用范围**：任意基础 CRUD 模块（员工、订单、商品、客户、字典维护、流程审批等），不限于某类业务。

后续会接入 3 类消费者技能（页面渲染定制、业务接口开发定制、扩展点定制），它们都会消费生成器产出的模型数据。

## 模型数据 schema

生成器产出 8 类表/记录。下游消费者技能（未来）读取这些：

| 表 | 存什么 |
|---|---|
| `md_module` | 模块基本信息（编码、名称、表名） |
| `md_field` | 字段定义（类型、长度、是否必填、字典） |
| `md_form` | 表单配置（编辑类型、校验、显示规则） |
| `md_button` | 按钮配置（6 个标准按钮：新增 / 查看 / 编辑 / 删除 / 导入 / 导出） |
| `sys_resource` | 菜单 / 按钮资源（权限粒度） |
| `sys_role_resource` | 角色授权（哪个角色能用哪个菜单） |
| `comm_dictionary` + `comm_dictionary_item` | 数据字典（下拉选项来源） |

如果 `module.flow_code` 非空，**自动额外注入** 7 个流程字段（`FLOW_ID` / `FLOW_NAME` / `FLOW_INSTANCE_ID` / `NODE_INSTANCE_ID` / `NODE_INSTANCE_NAME` / `BO_STATUS` / `NODE_CODE`）到业务表 + `BO_STATUS` 字典（草稿 / 审批中 / 已通过 / 已驳回）。

## 三步工作流

任何 CRUD 模块的开发都必须走这 3 步，缺一不可：

```bash
# 步骤 1: 生成 SQL
python3 .claude/skills/backend-module-generator/crud_generator.py \
    --def <project>/crud-generator/module_defs/<module>.json \
    --output <project>/crud-generator/output/

# 步骤 2: 执行 SQL（必须用 db_executor.py，不用 mysql CLI）
python3 .claude/skills/backend-module-generator/db_executor.py \
    <project>/crud-generator/output/<module>/v<version>/<module>_create.sql \
    --config-from-brain <project>/.trellis/PROJECT-BRAIN.md

# 步骤 3: 幂等性校验（必须 ALL PASSED 才算完成）
python3 .claude/skills/backend-module-generator/validators/idempotent_check.py \
    <project>/crud-generator/module_defs/<module>.json
# → 退出码 0 + 输出 "ALL PASSED ✅" 才算通过
```

**跳过任何一步 = 不算完成。** 详见 `verification-before-completion` 技能。

## 三种场景

读生成器内置的 rules 文档决定细节：

| 场景 | 读什么 |
|---|---|
| 单表 CRUD（无关联、无流程） | `rules/BASIC-CRUD.md` |
| 多表关联（含 `md_module_link`） | `rules/MODULE-LINK.md` |
| 流程引擎（`module.flow_code` 非空） | `rules/FLOW-ENGINE.md` |

**含流程引擎 + CRUD**（最复杂）：拆成两个 JSON（`flow.json` + `module.json`），先跑 `--flow-only` 再跑 `--def`。

## 多项目隔离

- **DB 配置**：永远从 `<project>/.trellis/PROJECT-BRAIN.md` 读取，不硬编码连接。
- **输出路径**：`<project>/crud-generator/output/<module>/v<version>/`，已在 `.gitignore`。
- **跨项目禁止**：不要把项目 A 的 `module.json` 跑到项目 B 的库。
- **多人协作**：同时改 `PROJECT-BRAIN.md` 会冲突，先 git pull 再改。

## CLI 标志速查

| Flag | 用途 |
|---|---|
| `--def <json>` | 指定模块定义 JSON |
| `--output <dir>` | 指定输出目录（默认 `./output`） |
| `--dry-run` | 只预览 SQL，不写文件 |
| `--validate` | 只校验 JSON 合法性，不生成 |
| `--config-from-brain <path>` | 从 PROJECT-BRAIN.md 读 DB 配置 |
| `--flow-only <flow.json>` | 只生成流程引擎 7 表，不生成模块 |
| `--flow-execute` | 与 `--flow-only` 配合，直接执行到 DB |
| `--flow-clean` | 与 `--flow-only` 配合，只清理不创建 |

## 不要做

- **不**手编 `crud-generator/output/` 下的 SQL——改了等于绕过生成器，下次重跑会覆盖。
- **不**跳 `idempotent_check.py`——它检查字典三条件、流程字段冲突等 8 类问题，跳过必踩坑。
- **不**对同一 DB 并行跑多个 `crud_generator.py --def`——MySQL 用户变量冲突导致数据错乱（详见 `dispatching-parallel-agents` 技能）。
- **不**跨项目用错 `PROJECT-BRAIN.md`——会污染其他库。
