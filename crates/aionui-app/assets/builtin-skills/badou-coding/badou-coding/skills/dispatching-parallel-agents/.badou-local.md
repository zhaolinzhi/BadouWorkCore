## 不要并行跑生成器

**不要**在两个子 agent 里并行跑：
- `crud_generator.py --def A.json`
- `crud_generator.py --def B.json`

**原因**：`crud_generator.py` 生成的 SQL 大量用 MySQL 用户变量（`@module_id` / `@field_xxx` / `@menu_resource_id`），依赖**单个连接的会话上下文**。并行执行时两个子 agent 的连接各自维护变量集，第二个 agent 的 `@module_id` 可能是第一个 agent 的残留值，**静默数据错乱**（无报错，但记录串台）。

## 可以并行的场景

| 场景 | 能否并行 | 原因 |
|---|---|---|
| 跨项目（不同 DB / 不同 PROJECT-BRAIN.md） | ✅ | 互不影响 |
| 准备阶段（写多个 `module.json` 文件） | ✅ | 纯文件 I/O |
| 生成后定制（一个子 agent 写一个 service 层） | ✅ | 不跑生成器 |
| 同 DB 跑多个生成器 | ❌ | 上述变量冲突 |

## 安全模式

需要批量生成 N 个模块到同 DB 时：

```python
# 单子 agent 串行循环
for json_path in module_jsons:
    subprocess.run([
        "python3", "crud_generator.py",
        "--def", json_path,
        "--output", "./output"
    ], check=True)
    subprocess.run([
        "python3", "idempotent_check.py", json_path
    ], check=True)
```

**不要**用 `subprocess.Popen` 并发；用 `subprocess.run` 串行。
